# 测试用例与回归规则

维护版本：V1.0.1，2026-10-30。需求见 [需求记录](requirements.md)，当前结果见 [V1.0.1 测试报告](test-results/2026-10-30-v1.0.1.md)。用例描述“应该怎样”，报告记录“实际怎样”，两者不能混用。

## 每次开发的执行规则

1. 为新需求确定编号和验收条件，先设计正常路径、异常/边界路径以及受影响旧功能的用例。修复缺陷时尽量先复现，保留能捕获缺陷的回归测试。
2. 可确定性重放的逻辑写入 `tests/*.test.mjs`，使用 Node 内置测试器，无需新增测试框架。浏览器视觉、交互、无障碍与硬件手感使用下表的浏览器/人工用例。
3. 完成修改后运行 `pnpm verify`：自动测试 → Astro 类型/内容检查 → 静态构建 → 站内链接和资源校验。GitHub Actions 也执行同一个命令，失败则不进入部署。
4. 每次发布执行 B01、B08–B12、B15 的基本冒烟；改动输入、动效或响应式时增加 B02–B07、B13–B14；改动内容模型/路由时增加 C01–C03、S01–S06、B16–B18。新特性的专项用例不得被这份固定清单替代。
5. 在 `docs/test-results/日期-版本.md` 写入环境、目标代码、步骤、实际结果和未覆盖项。失败必须定位、修复并重跑；未经执行不能填写“通过”。硬件验证与合成事件测试明确区分。
6. 发布后确认对应提交的 Actions 成功，再打开线上首页和一件作品验证。记录发布提交与运行链接。纯测试记录的后补更新仍须遵循发布流程。

## 自动测试：输入识别

实现：`tests/wheel-navigation.test.mjs`。共同前置：创建独立识别器，按显式时间戳喂入合成滚轮轨迹；不依赖真实计时器或浏览器。基础轻扫序列为 `[12,24,42,36,28,20,14,9,5,3,2,1]`，默认间隔 16ms；这些是模拟数据，非物理触控板录制。需求 R04、R12。

| ID | 操作 / 输入 | 预期结果 |
| --- | --- | --- |
| W01 | 一次基础轻扫及惯性尾部 | 只产生一次下一项 |
| W02 | 基础轻扫尾部后立即接另一加速序列，无 180ms 空白 | 产生两次下一项，复现并防止本次漏滑问题 |
| W03 | `[20,25,-14,-28]`，在动画内反向 | 先下一项，再上一项 |
| W04 | 两个 50px 输入间隔 140ms | 两次均响应，不等待旧 460ms 锁 |
| W05 | 首次轻扫后接 150 个单调衰减采样 | 总计一次选择，不惯性连跳 |
| W06 | 尾部中插入孤立 55px 尖峰，随后回到极小量 | 不因单个异常事件多跳 |
| W07 | 尾部混入小于 3px 的反弹与亚像素噪声 | 不额外选择或误反向 |
| W08 | 尾部后缓慢增加到 2、3、4、5、6、8、10、12px | 较轻的新一轮手势也能触发 |
| W09 | 持续输入 70 个 12px 采样 | 可以继续浏览，连续推进间隔不少于 220ms |
| W10 | 连续 6 次正向、6 次反向基础轻扫 | 12 次都响应，不永久锁住 |
| W11 | 行/页模式离散输入，相隔 50ms | 每个明确步骤都响应 |
| W12 | 未达阈值时切换输入方式，重置后再滚动 | 不继承旧累积量造成误切 |
| W13 | 矮窗口正文区域进行水平输入 | 返回有效的作品导航输入 |
| W14 | 矮窗口正文垂直滚动；再移到作品栏内滚动 | 正文不拦截，作品栏可选择 |
| W15 | 纯纵向以及水平占优的斜向输入 | 上下映射左右；斜向方向正确 |
| W16 | 像素、行、页三种单位 | 统一成预期像素量，符号保留 |
| W17 | Ctrl 捏合、Command 修饰、开场期间 | 均不导航作品 |
| W18 | 非有限数、零、微动、未达阈值的正负摆动 | 不产生选择，不污染状态 |
| W19 | 基础轻扫尾部后连续输入 12 个 4px 低幅度采样 | 第二次轻扫仍可累积触发，不要求大幅度甩动 |

## 构建校验

由 `scripts/verify-build.mjs` 和 `astro check/build` 执行，前置为项目依赖安装完成。需求 R06、R08、R16。

| ID | 检查方法 | 预期结果 |
| --- | --- | --- |
| S01 | 检查内容字段与 Astro/TypeScript | 无错误，缺失必要字段应导致构建失败 |
| S02 | 遍历构建后的每个 HTML 的站内 href/src | 目标页面或素材存在，不越出 dist |
| S03 | 检查页面标题和 HTML id | 标题非空，无重复 id |
| S04 | 检查首页选择栏和面板 | 数量一致，默认选中项唯一，控制关系一一对应 |
| S05 | 检查 sitemap 和旧路径构建产物 | sitemap 包含作品，旧入口文件存在 |
| S06 | 检索原型占位语句 | 正式页面没有残留“设计样稿”等提示 |

## 新用例模板

每个新用例必须包含：唯一 ID、需求编号、前置条件、具体输入与步骤、明确的预期结果、自动化文件或人工方法。失败记录还要包含实际结果、复现条件、处理方式和复测结果。不能以“看起来正常”替代对应的可观察标准。
